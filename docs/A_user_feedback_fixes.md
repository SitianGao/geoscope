# 用户反馈修复记录（2026-11-18）

## “最下面的船”被执行成全图船舶

已在用户实际使用的服务器找到原始影像与错误记录：image_id `7c8d57152d4b`，2250×2269，旧结果 `628d33918a0e`，query 为“提取最下面的船”，实际 service_request 却是 semantic_seg / ship，面积 891,767 px（17.47%）。

原因是旧 Agent 系统提示要求所有分割转成整图类别，且 Harness 未把对象位置作为必须保留的合同。现在明确区分对象位置指代和像素半幅：极值位置任务只开放指代工具，context.reference 中的规范提示必须保留。丢失位置、切换成类别工具或 all ships 时直接停止，不能伪装成功。ROI/半幅冲突、多个对象和含糊位置先澄清。

原图真实 Agent→SAM 复测的新版本 `e8e1eb4a6be7`：请求 text 为 `the bottommost ship`，120,398 px（2.36%）。实际叠加图仅最底部船舶高亮，已人工检查截图；不据此宣称对所有影像的分割准确率。标题/版本/范围标签显示单目标指代，不再写“全图船舶已生成”。旧错误版本的蒙版保留，显示需重跑告警并禁止误确认。

普通类别整图和半幅路径保留。针对单目标位置不运行局部切片/AFR，避免在每个 tile 重新解释“最下面”。位置限定、请求、图像绑定、实际模式、缓存与反馈均可追溯。新增合同和负例测试，不使用模型输出数字替代蒙版统计。

## 检索界面可读性

- 主要界面保留影像预览、名称、原图尺寸、排序和三位小数的相似度。
- 长 image_id、原图 SHA256、原始分数和模型/索引版本移到可展开的追溯记录；API 数值不变。
- 返回数量随实际图库调整，三幅影像时不再默认要求五条；按钮对齐，名称统一留出空间，桌面不再因长哈希被迫滚动。
- 手机改为单列卡片，无横向溢出；空库、断连、检索中、无结果及打开失败均有真实反馈。
- 使用服务器真实 Chrome 检查桌面/手机、缩略图、原始精度追溯和实际选图；没有拦截真实检索响应。

## 其他收尾

实际热重启遇到端口释放/ TIME_WAIT 窗口，服务管理检查增加 SO_REUSEADDR 与有限等待；仍拒绝接管他人监听端口。新增已完成 TCP 连接后的重启用例，生命周期测试只清理自己创建的子进程。服务继续在服务器 GPU0 运行。
