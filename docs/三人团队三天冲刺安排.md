# GeoScope 三人团队三天冲刺安排

> 适用版本：GeoScope v0.5.0 / 技术方案 v4  
> 团队人数：3 人（队长、队员 A、队员 B）  
> 冲刺目标：把“已经跑通的 Demo”补成“有多图数据、有对照实验、有用户证据、可稳定答辩的参赛作品”  
> 执行原则：三天内停止扩展新模型，集中验证 RemoteAgent + GeoScope Harness + RemoteSAM 主链路

---

## 一、当前起点

团队已经完成：

- RemoteAgent 官方权重和 vLLM 服务部署；
- RemoteSAM 官方权重和 `/predict` 服务部署；
- RemoteAgent → Harness → RemoteSAM → 统计 → 结果回填的真实闭环；
- 场景问答、目标提取、左右条件修改、版本保存、失败保护和实验包导出；
- GeoScope v0.5.0 可交互 Demo；
- 整仓 51 项自动检查和浏览器流程检查；
- 技术方案 v4。

因此，未来三天不再把时间用在“模型能不能启动”上。当前主要缺口是：

1. 多幅影像上的分割精度证据；
2. 多类任务上的 Agent 决策和端到端完成率；
3. 与人工流程、基础 Agent 流程的对照结果；
4. 真实目标用户的操作时间和反馈；
5. 固定、稳定、可复现的答辩版本。

---

## 二、三天结束时必须交付什么

### 2.1 最低验收线

三天结束时至少应具备：

- 20 幅来源明确、可用于评测的遥感影像；
- 建筑、飞机两个核心类别；
- 40 条结构化任务，覆盖直接回答、全图提取、左右/上下约束、连续修改、含糊任务和失败任务；
- RemoteSAM 的 IoU、Dice、推理耗时统计；
- RemoteAgent 的任务路由正确率、合法工具调用率和失败类型统计；
- 6 名目标用户，每人完成 4 个统一任务；
- 人工流程、基础 Agent、GeoScope 三组对照表；
- 一份实验结果报告；
- 一个冻结的演示版本、一套三分钟讲解词和一份备用录屏；
- 代码、结果表格、版本号和运行说明能够对应。

### 2.2 冲刺目标

如果进度顺利，将规模提高到：

- 30 幅影像；
- 60 条任务；
- 8—10 名目标用户；
- 增加 Boundary F1、空间条件满足率和失败恢复率；
- 请师兄抽查至少 5 个成功案例和 3 个失败案例。

最低验收线完成前，不增加道路、水体等新类别，也不增加新的 Remote 系列模型。

## 三、固定分工

| 成员 | 三天主责 | 不负责的内容 | 最终交付 |
|---|---|---|---|
| 队长 | 实验规则、工作台整合、用户试用、总验收、材料和答辩 | 不代替 A/B 重做模型部署 | 汇总数据、用户实验、最终 Demo、报告、PPT素材 |
| 队员 A | RemoteAgent 任务评测、基础 Agent 对照、动作失败分析 | 不修改 RemoteSAM 推理服务，不重做前端 | Agent 评测脚本、逐任务结果、指标和失败案例 |
| 队员 B | RemoteSAM 多图评测、分割精度、性能和失败分析 | 不修改 Agent 和 Harness 主流程 | 数据清单、逐图指标、汇总指标、可视化案例 |

### 共同规则

- 每个人都从最新 `main` 开始工作；
- 队员 A 使用 `feature/competition-agent-eval`；
- 队员 B 使用 `feature/competition-sam-eval`；
- 不直接向 `main` 强制推送，由队长验收后合并；
- 权重、令牌、`.env`、校园网地址、未经授权的原始数据不提交 Git；
- 提交结果必须包含原始逐条记录，不能只交一张截图或一个平均数；
- 模拟服务结果和真实模型结果分别标记，不能混在同一统计中；
- 所有指标由脚本根据真实结果生成，不手工填写“好看的数字”。

   - 影像编号；
   - 数据来源与许可说明；

4. 选择 20 幅最低评测影像，冲刺目标为 30 幅；
5. 将同一份影像编号和任务编号发给 A、B，禁止两人各用一套编号。

#### 下午

   - 询问影像主要场景；

4. 联系至少 6 名遥感/GIS 学生或科研人员，确定第 2 天的试用时段；
5. 请师兄确认核心类别、数据来源和语义判断标准。

#### 队长当日交付

- `evaluation/dataset_manifest.csv`；

- 一次最新真实闭环记录；

#### 队长验收标准

- 每幅影像都有编号和来源；
- 每条任务都有期望动作和完成条件；

- 至少 6 名用户已经确定试用时间；
