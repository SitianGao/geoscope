# 三人协作约定

## 当前目录

```text
geoscope/
  server.py                    队长：工作台与 Harness
  web/                         队长：交互界面
  tests/                       工作台测试
  services/
    remoteagent/upstream/      A：RemoteAgent 认知核心源码
    remotesam/upstream/        B：RemoteSAM 服务与模型源码
  docs/                        项目方案、进度与交接说明
```

旧交接文档中的文件路径是原始资料库路径。本仓库开发时，以本目录映射为准。工作台就在仓库根目录；两个模型的源代码入口如上。

## 分支和交付

- `main`：共同验收的版本。
- `feature/workbench`：队长负责工作台与系统集成。
- `feature/remoteagent`：A 负责认知核心。
- `feature/remotesam`：B 负责分割服务。

上述为分支命名约定，分支存在情况以 GitHub 为准。第一次开发从最新 main 创建；后续每个独立改动可创建新功能分支。每人提交自己负责的改动，通过 PR 合并到 main。不要强制推送、覆盖其他人的提交。

GitHub 网页可查看文件、修改文字说明和审查 PR；需要运行模型或测试的工作在克隆后的本地或计算服务器完成，再提交和推送。

每次 PR 说明：解决了什么问题、运行方式、实际测试证据、未解决的问题。模拟接口测试与真实模型推理必须区分。不要只交截图。

## 模型和接口

两个模型使用独立环境，不把旧 RemoteSAM 依赖安装进工作台或 Agent 的环境。第一天约定 Agent 与 Harness 的调用边界，避免两套执行循环重复调用分割服务。

RemoteSAM 默认接口合同见 `services/remotesam/README.md`。像素范围筛选、统计和版本归队长管理。

权重从官方来源下载，记录位置和版本；源码仓库不保存权重、实验数据、密钥、缓存或虚拟环境。工作台支持根目录 .env；将 .env.example 复制后填写真实配置，已有进程环境变量优先。

2026-09-20 的队长侧交付见 [队长执行与验收](队长执行与验收.md)，当前对接合同见 [接口与联调约定](接口与联调约定.md)。旧交接说明与这两份文件不一致时，以这里的最新状态为准。真实模型联调尚未完成。

## 日常进度

上午确认当天交付，晚上提交可验证的接口、文件和日志。第 2 天两个模型独立运行，第 3 天完成端到端，第 5 天冻结功能，第 6—7 天测试与演示。

GitHub 项目管理员需要在仓库 Settings 的协作者设置中邀请两名队员。他们接受邀请后才能访问私有仓库并推送。
