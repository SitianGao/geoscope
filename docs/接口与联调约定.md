# 工作台与模型服务的联调约定

状态：2026-09-22 已按 A/B 合并后的代码实现。RemoteAgent 与 RemoteSAM 已分别完成官方权重真图验证；工作台使用 A 的规划/反馈接口，由 Harness 独占工具执行权，再调用 B 的 RemoteSAM HTTP 服务。当前只差保存一次两个服务同时在线的完整现场闭环记录。

## 1. 目录与执行责任

队长修改根目录工作台、几何工具和实验文件。A 修改 `services/remoteagent/`；B 修改 `services/remotesam/`。A 的 `plan` 只返回决策，工具执行由 Harness 负责；禁止同一请求中同时调用 A 的自执行 `run` 和 Harness 工具循环。

## 2. A 必须交付的接口

以 A 的 efce7b8 提交提出的接口为依据：

- `RemoteAgent.plan(query, image_path, context=...)`：输入当前真实影像和上下文，返回 AgentResult。
- `RemoteAgent.continue_with_tool_result(query, image_path, decision, tool_result, context=...)`：接收真实执行结果再回答。
- `completed`：仅表示直接文本回答完成；不能据此标记分割产物已经生成。
- `tool_call`：返回 `tool_call.name` 和 `tool_call.arguments`；只允许双方约定的分割工具。
- `rejected_tool`、`unparsed`：停止执行，保留旧版本，不猜测执行参数。
- `raw_response`、`history`：保留模型实际响应与调用记录，记录为可观察事件，不伪造推理链。

**尚需 A 明确的字段：**目标类别、全图分割提示和 `side=all/left/right/top/bottom` 如何交给 Harness。当前 plan 合同只有工具名与参数，没有独立的空间条件字段。不能把旧 Demo 的关键词解析静默当作官方 Agent 的空间理解能力。可以采用显式范围选择或可验证的结构化任务字段，确认后再接入。

澄清和导出是实验交互动作，不强行写成不存在的官方工具。A 的接口尚未定义专门澄清状态，需要共同约定；不将所有直接回答自动判为澄清。

工具反馈中包含执行状态、文件标识、像素面积、比例、空间范围和失败原因；不将大幅 base64 蒙版放入文本上下文。模型回答与统计不一致时以确定性统计为准，必须记录差异。

## 3. B 的 HTTP 接口

请求 `POST /predict`：

```json
{"task":"referring_seg","image":"<base64 PNG，不含data URL前缀>","text":"all buildings"}
```

成功响应：

```json
{"status":"success","mask":"<base64单通道PNG>"}
```

- 蒙版必须与输入图像尺寸和坐标一致。
- 可接受 0/1 或 0/255 二值值域；概率图、多类别标签图不能混用。
- 全零蒙版是一次成功请求的“未检出”，不是服务错误，不得断言现实不存在目标。
- B 输出完整目标蒙版；左右半幅由 Harness 统一裁切。
- 推理失败返回明确 HTTP 错误或 `status=error`。不以固定空蒙版掩盖错误。
- 建议增加 `GET /ready`，返回 `{"ready":true}` 或 `{"status":"ready"}`；模型未加载时不能声明 ready。没有 /ready 时工作台会标记就绪未知，需要单独测试 /predict。

## 4. 地址和版本配置

把根目录 `.env.example` 复制为 `.env`，填写 A/B 确认的信息后重启工作台。

| 变量 | 要填什么 |
|---|---|
| GEO_AGENT_BASE_URL | 当前旧适配使用带 `/v1` 的根地址，不能重复添加 `/v1` |
| GEO_AGENT_MODEL | `/v1/models` 实际返回的模型 id，不猜测名称 |
| GEO_AGENT_API_KEY | 需要认证时填写，不进入前端或 Git |
| GEO_REMOTESAM_URL | B 提供并验收的 `/predict` 地址 |
| GEO_REMOTESAM_REVISION | B 确认的权重及推理配置版本；为空时禁用真实分割缓存复用 |
| GEO_SERVICE_PROXY_MODE | 默认 direct，模型服务直连；仅确实需要代理时用 environment |

A 上游客户端的 `VLLM_URL` 不带 `/v1`，与工作台的 `GEO_AGENT_BASE_URL` 约定不同，联调时要区分。`.env` 不支持执行命令或变量展开，同名进程环境变量优先。

模型服务连接与下载代理是两件事。不能将本机的 127.0.0.1 代理直接当作服务器上的代理。工作台能否访问实验室 IP，还取决于所在网络和既定访问方式。

## 5. 缓存与产物

每次分割保留内部 `full_mask.png`，再生成当前范围的 `mask.png`。复用需匹配影像、目标、标准提示、服务地址及模型版本，并验证完整蒙版文件哈希。改变任一项或用户要求重新推理时不复用。旧版本文件不覆盖。

对外 ZIP 保持六项：original.png、mask.png、overlay.png、result.json、statistics.json、run_log.json。full_mask.png 作为内部复用资产保留，不改变现有六文件交付约定。

## 6. 合并门槛

必须能在全新检出的仓库里导入和运行测试；不能依赖未提交的本地辅助函数。模拟测试证明接口处理，不证明官方模型能力。真实上线前额外提供模型版本、实际请求响应、新影像结果以及至少一个失败案例。
