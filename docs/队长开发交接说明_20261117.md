### 1. GeoScope-AFR 核心算法（队长独占 `geoscope_algorithms/`，纯 numpy）

| 文件 | 内容 |
|---|---|
| `region_scoring.py` | 区域难度估计 U=α·H̄+β·D̄+γ·C̄（熵/边缘密度/分歧；熵在 8-bit 量化概率上计算并裁剪非负；空蒙版只打标记） |
| `adaptive_refinement.py` | 预算贪心选择（Budget max_regions/fraction）；tile_grid 与服务端 `_tile_positions` 逐字节对齐；局部推理（裁剪+小区域×2 放大）；区域失败只记录不抛出 |
| `fusion.py` | 跨尺度融合 P_f=(1-λ)P0+λ·P_local，重叠区逐像素平均，λ∈[0,1] 校验；threshold_binary 默认 0.5 |
| `consistency.py` | 分歧图 D=\|M_whole−M_local\|、per-region 统计、待复核列表；IoU 空集规则（双空=1、单空=0）；强制声明"分歧≠错误概率" |
| `adaptive_runner.py` | 编排器（transport 注入）：P0→打分→选择→局部推理→融合→诊断；AFRInitializationError 触发整体回退；确定性无 RNG；config_fingerprint 供缓存隔离 |

### 当前卡点：cuDNN 不兼容（正在解决）

- 现象：/predict 报 `RuntimeError: cuDNN error: CUDNN_STATUS_NOT_INITIALIZED`；fp16 开/关都复现；最小卷积复现（`torch.backends.cudnn.enabled=False` 时卷积正常）
- 根因判断：驱动 525.89.02 太老，与 torch 2.4.1+cu121 自带 cuDNN 8.9 不兼容
- **解决方案（进行中）**：换 `torch==2.4.1+cu118` + `torchvision==0.19.1+cu118`（525 驱动对 CUDA 11.8 成熟支持）。安装命令已在实验室机器后台跑：
  ```bash
  cd /home/gst/geoscope-national
  UV_HTTP_TIMEOUT=300 uv pip install --reinstall --python .venv/bin/python \
    'torch==2.4.1+cu118' 'torchvision==0.19.1+cu118' \
    --index-url https://download.pytorch.org/whl/cu118
  ```
- **接手第一步：检查该安装是否完成**（约 2.4GB 下载）：
  ```bash
  ssh gst@10.199.139.30 "/home/gst/geoscope-national/.venv/bin/python -c \"import torch; print(torch.__version__)\""
  # 期望 torch 2.4.1+cu118；再验证 cudnn 卷积：
  ```

- 若 cu118 仍失败：备选 = 禁用 cuDNN（`echo "import torch; torch.backends.cudnn.enabled=False" > .venv/lib/python3.10/site-packages/sitecustomize.py`，慢但可用）
