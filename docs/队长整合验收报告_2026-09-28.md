|---|---:|---|
| 任务路由正确率 | 75.0%（30/40） | 仍有四分之一任务未按预期完成决策 |
| 合法工具调用率 | 76.9%（20/26） | 在可识别的工具调用中，有 6 次调用了未部署工具 |
| 已执行任务目标类别正确率 | 100%（16/16） | 只针对最终通过 Harness 并形成分割计划的任务 |
| 已执行任务空间条件正确率 | 100%（16/16） | 空间条件由 Harness 的确定性规则保证 |
| 澄清任务识别率 | 100%（6/6） | 含糊或越界任务没有被强行执行 |
| 平均 / 中位决策耗时 | 2524.8 / 2447.0 ms | 38 次真实模型调用；中位数由中间两项平均 |

Harness 对 6 次非法工具、3 次无法解析输出、4 次参数越界和 1 次以文字冒充分割结果进行了拦截或拒绝。这证明 Harness 能让失败显式暴露，但不能把失败的 Agent 决策变成成功任务，因此 75.0% 才是当前应对外报告的路由结果。

飞机类只有 1/6 路由成功，是最突出的决策短板。主要失败包括误选目标检测工具、英文推理过长导致工具动作未解析、工具名漂移以及把空间条件写入模型参数。

### 4.1 飞机专项改进

队员 B 在相同 10 张飞机诊断图、相同真值和相同权重上完成 16 组、160 条逐图实验。队长已从合并 CSV 独立复算全部 TP、FP、FN、IoU、Dice、实验覆盖范围和汇总值。

| 方法 | 飞机平均 IoU | 平均 Dice | 平均服务耗时/图 | 产品定位 |
|---|---:|---:|---:|---|
| 原基线 `all airplanes` | 0.1585 | 0.2281 | 658 ms | 冻结基线 |
| 整图 `all planes` | 0.2460 | 0.3292 | 441 ms | 快速模式，已接入主流程提示词 |
| 1.25 倍放大 + `all planes` | 0.2470 | 0.3300 | 601 ms | 收益很小，不采用 |
| 1024 切片 / 重叠 256 / 阈值 0.88 | **0.3056** | **0.4133** | 5659 ms | 高精度候选模式 |

最佳方案相对基线绝对提高 0.1471、相对提高约 92.8%，达到阶段目标 IoU ≥ 0.25。代价是平均客户端墙钟时间约 12.39 秒/图，10 图共发出 237 次切片请求。阈值 0.88 在同一组诊断图上选择，因此该结果是固定诊断集上的改进证据，不是独立测试集上的泛化成绩。

20 幅输出全部通过尺寸一致、二值合法与非空检查。平均服务推理耗时为 313.4 ms，中位数为 267.6 ms。3 幅重复测试产生一致指标，说明在固定输入和当前权重下结果可重复。

## 5. 系统级解释

这两套实验回答的是两个不同问题：

1. RemoteAgent 评测回答“系统是否选对动作、Harness 是否能拦住错误动作”；
2. RemoteSAM 评测回答“在固定文本提示下，分割工具的输出和真值有多接近”。

不能把 75.0% 与 0.2554 相乘并称为“系统总准确率”，也不能把 16 个通过 Harness 的任务与另一批 20 幅图拼成端到端成功率。真正的端到端精度必须让同一批任务按 `RemoteAgent → Harness → RemoteSAM → 统计` 完整执行后再与真值逐项比较。

主流程飞机快速模式现统一使用 `all planes`，这是当前诊断集上整图直推的最佳提示词。切片方案暂不设为默认，因为耗时明显增加且阈值仍需独立样本验证。上述修改不会追溯性改变已经产生的 40 条 Agent 结果或 20 幅基线分割结果。

## 6. 队长独立复算

运行：

```powershell
python evaluation/recompute_integrated_metrics.py --write
```

脚本执行以下检查：

- 从 40 条任务 CSV 复算路由、工具合法性、目标、空间、澄清与耗时指标；
- 从每幅图的 TP、FP、FN 复算 IoU 和 Dice；
- 检查 RemoteSAM 输出尺寸、二值合同、类别均值和总体均值；
- 核对飞机专项 160 条记录、16 组完整覆盖、最佳配置、耗时和提升幅度；
- 与两位队员提交的汇总 JSON 逐项核对，不访问模型服务。

复算结果保存在 `evaluation/results/captain_integrated_summary.json`。本次还纠正了队员 A 汇总程序对偶数样本中位数的计算：正确值为 2447.0 ms，原记录 2452.3 ms 是取了排序后靠上的单项。
